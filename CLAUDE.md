# LAMP — мультитенантная ATS

Проект ведёт человек без опыта разработки. Все объяснения — на русском, по шагам,
без предположений о знании терминологии. Не переходить к следующему этапу,
пока текущий не работает.

## Стек

- Next.js 16 (App Router) + React 19 + TypeScript
- Tailwind CSS 4, палитра в `src/app/globals.css`
- Prisma 7.10.0 (зафиксировано точно: тег `latest` указывает на нестабильный 8.0-rc)
- PostgreSQL в Neon (Frankfurt), подключение через `@prisma/adapter-pg`
- Проверка данных — zod, иконки — lucide-react

## Команды

- `npm run dev` — сервер разработки на http://localhost:3000
- `npm run db:migrate` — применить изменения схемы к базе
- `npm run db:studio` — визуальный просмотр базы
- `npm run db:check` — проверка подключения и количества записей
- `npm test` — автоматические проверки (vitest, папка tests)
- `npm run resume:check -- путь/к/папке` — прогнать папку с резюме
  и посмотреть, что распозналось и на сколько процентов
- `npm run resume:reparse` — перечитать резюме всех кандидатов после
  доработок разборщика (`-- --force` заменит и уже заполненный опыт)
- `npm run qa:seed` / `npm run qa:clean` — тестовая компания с данными
- `npm run grant-owner -- почта@пример.kz` — сделать человека владельцем системы
  (добавить `--revoke`, чтобы снять; без аргументов — список владельцев)
- `npm run build` — сборка версии для публикации

## Правила проекта

1. Изоляция компаний: любой запрос к данным обязан фильтроваться по `companyId`
   из сессии. Никогда не доверять `companyId` из формы или адреса страницы.
2. Права проверяются на сервере, а не только скрытием кнопок в интерфейсе.
   Исключение из правила 1 — владелец системы (`User.isSuperAdmin`): раздел
   `/system` работает поверх компаний. Каждое его действие начинается с
   `requireOwner()` из `src/lib/superadmin.ts`, флаг нельзя выдать себе
   через обычный интерфейс компании.
3. Пароли — только через `src/lib/password.ts` (scrypt), в базе лежит отпечаток.
4. Сессии — `src/lib/session.ts`, в cookie случайный ключ, в базе его sha256.
5. Важные действия пишутся в `AuditLog` через `src/lib/audit.ts`.
6. Идентификаторы — cuid, не последовательные номера.

## Разбор резюме

Модуль в `src/lib/resume/`. Работает целиком на нашем сервере,
без обращений к нейросетям — только правила, шаблоны и словари.
Поэтому один и тот же файл всегда даёт один результат.

- `pipeline.ts` — порядок этапов, точка входа `processResume`
- `extract-text.ts` — текст из PDF (по координатам, с учётом колонок),
  DOCX, RTF и TXT
- `ocr.ts` — распознавание картинок и сканов, Tesseract локально
- `parse.ts` — разделы и поля шаблонами
- `skills.ts` — навыки по словарю, с синонимами
- `score.ts` — стаж по датам и полнота разбора
- `photo.ts` — фотография кандидата из PDF

Резюме бывают трёх видов, и все три надо держать в голове:
выгрузка с hh (русская и английская), дизайнерское резюме
(заголовки вразрядку, «должность · компания · город» одной строкой)
и скан. Имена бывают казахскими и латинскими — классы букв
собраны в `UPPER`/`LOWER` в parse.ts.

Фото берётся из первой страницы PDF: в выгрузке с hh там лежат
логотип hh 72×72 с прозрачностью и само фото покрупнее. Берём самую
большую картинку от 120 пикселей по стороне с пропорциями портрета,
ужимаем до 400 и кладём в хранилище отдельным файлом. Отдаётся
через `/api/candidates/[id]/photo` с теми же проверками, что и резюме.
У кандидатов, заведённых раньше, фото появится после
`npm run resume:reparse`.

Правило: никаких внешних AI-сервисов в работе приложения.
Если нужна новая способность — словарь, шаблон или правило.

## Сбор резюме с hh

Расширение Chrome в папке `extension/` (там же README с установкой).
Оно НЕ обращается к LAMP по сети: собирает резюме в свою память
и выгружает одним JSON-файлом, который человек загружает на странице
«Кандидаты → Импорт с hh». Поэтому не нужны ни ключи доступа,
ни публичный адрес сервера — LAMP может работать хоть на localhost.

Расширение не вычитывает поля из вёрстки hh: оно берёт тот же PDF,
что отдаёт кнопка «Скачать», и его разбирает уже наш модуль. Из
разметки берутся только подсказки (имя, должность, город) — они идут
в `hints` и подставляются лишь туда, где разборщик ничего не нашёл.
Так смена вёрстки на hh не ломает сбор.

Приём — `src/app/api/candidates/import/route.ts`, по одному кандидату
за запрос: видно ход работы, и сбой на одном не роняет остальных.
Повторный импорт того же человека узнаётся по `Candidate.sourceUrl`.

Создание карточки из разобранного файла живёт в
`src/lib/candidate-from-resume.ts` — общее место для формы загрузки
и для импорта, чтобы поведение не разъезжалось.

Ограничения в расширении (30 резюме за раз, пауза 1,5–3 с) стоят
намеренно: соглашение hh запрещает автоматический сбор, и собирать
можно только то, к чему у компании и так есть доступ по её договору.

## Важно помнить

- После правки `prisma/schema.prisma`: сначала `npm run db:migrate`,
  затем ОБЯЗАТЕЛЬНО `npx prisma generate`, затем ПЕРЕЗАПУСТИТЬ `npm run dev`.
  migrate не обновляет клиент, а запущенный сервер держит старый в памяти.
- В регулярных выражениях \b и \w не работают с кириллицей (это особенность JavaScript).
  Использовать явные диапазоны `[а-яё]` и проверки вида `(?![а-яёa-z])`.
- tesseract.js и @napi-rs/canvas перечислены в serverExternalPackages
  в next.config.ts. Без этого Next перепаковывает их и распознавание
  падает с «Cannot find module ...worker-script».
- Хранилище файлов переключается через STORAGE_DRIVER (local или s3),
  остальной код обращается только к saveFile/loadFile/removeFile.
- Время интервью хранится в UTC, показывается в APP_TIMEZONE.

## Особенности окружения

- Windows. В shell этой сессии PATH может не содержать Node.js —
  используйте `export PATH="/c/Program Files/nodejs:$PATH"`.
- Документация Next.js 16 лежит локально: `node_modules/next/dist/docs/`.
